Reward models and rubrics as rewards

The other main reward tool: a model that outputs one number, trained with the Bradley-Terry loss. Then how rubrics are now used directly as rewards, and what that means for small judges.

Week 2 · Day 5 · Notes

One number per answer

A judge writes its grade; a reward model computes it in one forward pass. Both are proxies, and both can be combined with code checks and rubrics.

1

What a reward model is

A language model whose final layer is replaced by a single number output. It reads prompt + answer and returns a score in one forward pass, with no text generated. It's trained on preference pairs: (prompt, chosen, rejected), labelled by people or by a strong judge. That's the data classic RLHF collected.

2

Bradley-Terry

P(chosen beats rejected) = σ(r_chosen − r_rejected)      # σ(x) = 1 / (1 + e^(−x))
loss = −log σ(r_chosen − r_rejected)

Only differences matter, like chess ratings. In code, compute σ and the loss in a numerically stable way (no exp of a large positive number).

3

Evaluating a reward model

  • Pair accuracy on held-out pairs: how often the chosen answer gets the higher score.
  • Length-matched pairs: if accuracy drops a lot when both answers have similar length, the model mostly learned "longer is better".
  • It's still a proxy: Gao, Schulman and Hilton's overoptimization study was about reward models. Keep a held-out evaluation.
4

Generative reward models sit between: a judge model trained specifically to grade. Process rewards grade each reasoning step instead of only the final answer; they catch lucky answers built on wrong steps, but step labels are costly.

5

Rubrics as Rewards (Gunjal et al., Scale AI, 2025)

Write a rubric for each prompt, have a judge grade answers with it, and train with GRPO. This extends verifiable-style RL to areas like medicine and science, where code can't check the answer.

AggregationHowFinding
ExplicitJudge each item separately; normalized weighted sum (Essential 1.0, Important 0.7, Optional 0.3, Pitfall 0.9)More brittle
ImplicitJudge sees all items, gives one holistic 1–10 score, normalized to 0–1Worked best in their experiments

They also report that rubric guidance improved judge alignment at every judge size, with the largest gains for smaller judges: good news when your training judge must be small and fast.

Glossary

Reward model (RM)
A language model with a one-number output head.
Preference pair
A prompt with a chosen answer and a rejected answer.
Bradley-Terry
P(A beats B) = σ(r_A − r_B).
Sigmoid (σ)
1 / (1 + e^(−x)); squashes any number into 0–1.
BT loss
−log σ(r_chosen − r_rejected).
Pair accuracy
Share of held-out pairs where the chosen answer scores higher.
Length-matched pairs
Pairs whose answers have similar length, to test for length bias.
Generative reward model
A judge model trained specifically to grade.
Outcome reward
Grades only the final answer.
Process reward
Grades each step of the reasoning.
Rubrics as Rewards (RaR)
Per-prompt rubrics graded by a judge, used as the GRPO reward.
Explicit vs implicit
Weighted sum of per-item grades vs one holistic score using all items.

The maths of preferences

Bradley-Terry in plain Python, plus an explicit-vs-implicit rubric comparison on your Day 3 task.

Tasks

  1. Write rm/bt.py with:
    • bt_prob(r_a, r_b): σ(r_a − r_b), no overflow for huge differences
    • bt_loss(r_chosen, r_rejected): −log σ(difference), numerically stable
    • pair_accuracy(scores, pairs): share of (chosen, rejected) pairs ranked right; ties count ½; ValueError if empty
