Train on the train split only. Evaluating on problems you trained on measures memory, not skill.

2

Setup

  • GPU: free Colab T4 (16 GB). Kaggle's free GPUs work too, and can run a notebook in the background with "Save Version → Save & Run All".
  • Model: Qwen2.5-0.5B-Instruct, small enough to train for free.
  • LoRA: the base weights stay frozen; you train small adapter matrices added to some layers. Far less memory, and the adapter is a few MB to save.
  • Libraries: TRL's GRPOTrainer, or Unsloth's free GRPO Colab notebook as a template with your reward functions plugged in.
3

Freeze one system prompt

SYSTEM_PROMPT = ("Solve the problem step by step. "
                 "Then give only the final number inside <answer></answer>.")

Use this exact text for training and for both evaluations. Changing the prompt between runs is the easiest way to fool yourself.

4

Baseline numbers: accuracy, format, pass@k, mixed groups

  • Accuracy: share of the 200 greedy answers your verifier scores 1.0.
  • Format compliance: share with exactly one tag holding a number.
  • pass@k: on 50 problems, sample n = 8 at temperature 1.0. With c correct out of n, the unbiased estimate is below. It tells you what sampling can reach.
  • Mixed share: share of those 50 groups with both right and wrong answers. Only mixed groups give GRPO signal (Day 1).
pass@k = 1 − C(n − c, k) / C(n, k)        # = 1.0 when n − c < k
5

Training config (starting point)

config = GRPOConfig(
    output_dir="grpo-qwen05b",
    num_generations=8,            # 4 if you run out of memory
    max_completion_length=256,
    max_steps=250,
    logging_steps=5,
    save_steps=50,                # and push each checkpoint to the Hub
)                                 # keep the default learning rate for run 1
trainer = GRPOTrainer(model=model, args=config, train_dataset=train,
                      reward_funcs=[correctness_reward, format_reward],
                      peft_config=lora_config)
trainer.train()

Parameter names shift between TRL versions; check the GRPOConfig docs for the version you install. The batch is built from prompts × G completions, so batch settings must be compatible with num_generations.

Five curves to watch

CurveHealthy (small model)Warning signFirst thing to try
Correctness rewardSlow, small riseFlat while total reward risesRead rollouts: is a bonus being farmed?
Format rewardClimbs fast, then plateausDominates total rewardLower its weight
Group reward stdStays above 0Falls to ~0Prompts too easy/hard; check mixed share
KLGentle riseShoots upLower learning rate; check for hacks
Completion lengthWithin the limitPinned at the capRaise the cap or check truncation

Metric names in the logs differ by TRL version (for example reward_std, kl, per-function reward columns). Log each reward function separately. The kl curve only appears when beta > 0, and recent TRL versions default to 0 (Day 5 covers why).

7

After training: the table, then the reading

Re-run the exact baseline. Fill one table: accuracy, format rate, average length, before vs after. Then read 20 late-training completions yourself. Expect format to jump and accuracy to move a few points on a 0.5B model: a normal first result. If total reward rose but accuracy didn't, you've found your first reward-hacking lead, which is where Day 4 starts.

Part A: eval code. Part B: the real run.

Part A takes about 30 minutes and needs no GPU. Part B is most of today's 5 hours. Send me your code, your test output and your results table.

Part A · eval/eval_utils.py

  1. SYSTEM_PROMPT and build_messages(question): system + user messages.
  2. summarize(correct, fmt): {"n", "accuracy", "format_rate"} from your two reward lists.
  3. pass_at_k(n, c, k): the unbiased estimator.
  4. mixed_share(groups): share of groups whose rewards are not all equal.
