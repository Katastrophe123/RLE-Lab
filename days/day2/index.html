Day 2 · Notes

A verifier you can trust

A verifier turns a completion into a reward. Whatever it rewards, the model learns, mistakes included.

1

What a verifier is

A function: reward = verifier(completion, gold_answer). It runs thousands of times per training step with nobody watching, so every quirk in it is applied at scale.

2

Five properties to check

PrecisionNever rewards a wrong answer. The one that matters most.
RecallAccepts right answers written in valid but unusual ways.
DeterminismSame completion, same score, every time.
SpeedFast enough for millions of calls.
Gaming-resistantNo shortcut earns reward without solving the task.

Precision = TP / (TP + FP) = 40 / 45 = 0.89
Recall = TP / (TP + FN) = 40 / 48 = 0.83

A false negative wastes signal: a right answer earned nothing. A false positive teaches the wrong lesson: the wrong pattern gets a positive advantage, becomes more likely, earns more reward, and spreads. That feedback loop is reward hacking.

Compare exactly: floats lie

float

Decimal
>>> Decimal("0.1") + Decimal("0.2")

>>> Decimal("18.0") == Decimal("18")
True

Parse answers into decimal.Decimal, never float. Exact maths keeps the verifier deterministic, and 18.0 still equals 18.

6

Format bonus and the TRL signature

A small format_reward (0.1 when exactly one answer tag holds a number) helps early training learn the output shape. Keep it small and log it separately: as Day 1's group 3 showed, even 0.1 ranks a wrong answer above others.

def correctness_reward(completions, answer, **kwargs):
    # completions: list of model outputs (strings, or chat messages)
    # answer: your dataset's "answer" column, passed in by TRL
    return [1.0 if ok(c, a) else 0.0 for c, a in zip(completions, answer)]

trainer = GRPOTrainer(..., reward_funcs=[correctness_reward, format_reward])  # rewards are summed

Check the exact GRPOTrainer signature for the TRL version you install.

Glossary

Verifier
A function that turns a completion into a reward.
Gold answer
The correct answer from the dataset.
Parse
Find the answer inside the model's text, e.g. between answer tags.
Normalize
Rewrite numbers so equal values look equal: $1,000.00 → 1000.
Precision
Of the answers the verifier rewarded, the share that were truly correct.
Recall
Of the truly correct answers, the share the verifier rewarded.
False positive
A wrong answer that got rewarded. The dangerous one.
False negative
A right answer that got 0. Wastes signal.
Deterministic
The same input always gives the same score.
Floating point
How computers store decimals approximately: 0.1 + 0.2 ≠ 0.3.
Decimal
Python's exact decimal numbers. Used for comparing answers.
Rubric
A written checklist a judge model grades against.
Format reward
A small bonus for using the answer tag correctly. Log it separately.

Day 2 · Coding checkpoint

Write verifier.py and pass 20 tests

About 60 minutes. No AI help until the tests pass. Then paste your code, your test output and your rules file into the chat for review.

Spec

  1. extract_gold(answer_text): the text after ####, commas removed, stripped.
  2. parse_answer(completion): what's inside <answer>…</answer>, stripped. Exactly one tag, otherwise None.
  3. normalize(s): remove $, commas and spaces; return a Decimal if what's left is a plain number (optional minus, digits, optional decimals), else None.
  4. correctness_reward(completions, answer, **kwargs): one float per completion, 1.0 if the normalized answer equals the normalized gold. Completions may be strings or chat lists (use the last message's content).
  5. format_reward(completions, **kwargs): 0.1 if the single tag holds a number, else 0.0.

Also write notes/verifier_rules.md: every rule you chose, and why.
