Day 7 · Notes

Show your work

People hiring for RL and evaluation roles look for proof that you can run the loop, find problems and report honestly. Your repository is that proof.

1

The README, in seven parts

SectionWhat goes in it
SummaryOne paragraph. The result in numbers, with an interval or p-value.
SetupModel, dataset split, GPU, LoRA, the key GRPO settings.
Verifier rulesEvery rule and the reason for it. Link to the tests.
ResultsThe table (baseline, v1, v2), a chart, and your verdict.
What I learned3–5 bullets. The surprises, not the obvious.
LimitationsModel size, number of problems, seeds, one dataset.
ReproducePinned versions, seed, prompt file, config, exact commands.
2

Write results honestly

  • Lead with numbers. "Accuracy changed from 41% to 43% on 200 problems (p ≈ 0.42, within noise)" beats "great results".
  • Same evaluation for every row, including a baseline before any RL. Say n, and say if it's a single seed.
  • An interval next to each number. The 95% Wilson interval for 82/200 is 34.4–47.9%. To halve the interval's width you need about 4× the problems: width shrinks with the square root of n.
  • Honest charts. Label axes. Don't crop the vertical axis so a 2-point gap looks like a cliff. One idea per chart.
  • Report what didn't work, with your best guess why. A null result written clearly builds trust.

Reproducible and tidy

rle-week1/
├─ verifier/   verifier_v2.py, tests
├─ eval/       eval_utils.py, compare_runs.py, report.py
├─ rl/         train.py, grpo_math.py
├─ notes/      verifier_audit.md, grpo_variants.md, scaling.md
├─ results/    tables, charts, sample rollouts
└─ README.md

Pin versions (pip freeze > requirements.txt), record the seed, keep the prompt in a file, keep configs in files, and make pytest -q run every test. Push the LoRA adapter to the Hugging Face Hub with a model card so anyone can load it.

4

The public post and the interview story

Post (LinkedIn or X): open with the most surprising concrete finding ("a model can get full reward for writing 7 2"), then 3–4 plain sentences, one image, the link. No hype words.

Interview story: problem → what you did → what you measured → what you'd do next. Practise two 60-second answers: how the GRPO advantage works, and one verifier hole you found and fixed.

Glossary

README
The front page of a code repository.
Reproducible
Someone else can follow your steps and get the same numbers.
Limitation
An honest statement of what your result does not show.
Model card
A README for a model on its Hugging Face page.
Baseline
Your numbers before any RL, measured the same way.
Wilson interval
A 95% range for an accuracy that behaves well near 0% and 100%.
Null result
An experiment that found no clear difference. Still worth reporting.
Pinned versions
Exact library versions written down, e.g. in requirements.txt.
LLM judge
A language model that grades answers, usually against a rubric.
Agentic RL
Training a model that uses tools over many steps.
Credit assignment
Working out which steps earned a reward that only arrives at the end.
